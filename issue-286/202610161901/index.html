#286 An agent can pay $12.50 for a $22 coffee by adding a line with quantity -1

ready for human review

Today an agent can pay $12.50 for a $22 coffee by sending a cart of "1 coffee and −1 tea". The store's delegated-purchase check (`verifyDelegatedPurchase`) accepts it. This is confirmed on current main. `cartProblem()` in `packages/credentagent-gate/src/ap2/chain/purchase.ts:344-353` checks only `Number.isSafeInteger(line.quantity)`. The `checkout.line_items` evaluator in `constraints.ts` ignores lines whose quantity is zero or less. But `rederiveTotal` and the store's catalog `price` callback still subtract those lines, so the reduced total "matches" the catalog. After the fix, every cart line must have a whole-number quantity of at least 1 and an item price that is a whole number of minor units above 0. A cart that breaks this rule is refused at both ends: (a) `verifyDelegatedPurchase` refuses it with code `malformed` at the existing shape check, before any constraint, amount or price check runs; (b) the store-side quote, `Ap2Issuer.signCheckout` (`credentagent.ap2.signCheckout`, packages/credentagent-gate/src/ap2/issue.ts:156, the "#263 quote"), throws instead of signing it, so a store cannot hand an agent such a cart. `DelegatedPurchase.spend()` already runs `cartProblem`, so it also refuses such a cart. Out of scope here: the issue's "fix the demo's `/agent/quote`" item. That code (`stores.mjs` in the multi-store demo) is not in this repo. No `/agent/quote` exists here, and the in-repo example `examples/delegated-purchase/merchant.mjs` hard-codes quantity 1. That item has to be done in the demo repo; the PR description should say so. Nothing published is affected (0.5.0 doesn't include this code).

What changed

Closes the "−1 tea" hole (issue #286). Before this change, an agent could pay $12.50 for a $22 coffee by asking for "1 coffee and −1 tea". The spending-limit check skipped any line with a quantity of zero or less. The total still subtracted that line, though, so the cart stayed within every limit and its price matched an honest catalog. I reproduced this on main: the new test got `ok: true` before the fix. **What changed** - A new shared rule, `lineItemsProblem()` in `packages/credentagent-gate/src/ap2/from-gate.ts`. Every cart line must have an item id, a quantity that is a whole number of at least 1, and an item price that is a whole number of minor units above 0. - **Verifying a purchase:** `verifyDelegatedPurchase` applies the rule through its existing shape check (`cartProblem`). A bad cart is refused with `code: "malformed"` and a detail naming the line and its quantity or price. This happens before any limit, amount or price check runs. `DelegatedIntent.spend()` uses the same shape check, so an honest agent can't build such a proof either. - **Quoting a cart:** `Ap2Issuer.signCheckout` (`credentagent.ap2.signCheckout`, the store-side quote from #263) throws `refusing to quote this cart: line … has quantity -1 …` instead of signing. `ap2.checkout()` goes through `signCheckout`, so it refuses too. - **Docs:** the gate README's delegated-purchases section now says every line needs quantity ≥ 1 and a positive price, and how each side refuses a line that doesn't. The `cartProblem` and `signCheckout` doc comments say the same. **Not done here:** fixing the demo's `/agent/quote` (the issue's third bullet). That code is `stores.mjs` in the separate multi-store demo repo and has to be changed there. This repo has no `/agent/quote`, and `examples/delegated-purchase/merchant.mjs` hard-codes quantity 1. --- **Test fixture change:** the `merchant()` helper in `purchase.test.ts` now signs carts directly with the checkout key instead of calling `signCheckout`, because `signCheckout` now refuses the hostile carts these tests need. It also takes an optional unit price per line, and its catalog now prices each line at its own unit price times quantity. **Bypass evidence (AC5):** 1. With the whole rule disabled (`cartProblem` checking only that `line_items` is an array, and the `signCheckout` throw switched off), all 4 new tests fail. The three verifier tests get `expected { ok: true, … } to match object { ok: false, code: 'malformed' }`, and the `signCheckout` test gets `expected [Function] to throw an error`. 2. With only `|| line.quantity < 1` removed from the shared helper, the −1 tea test and the quantity-0/1.5 test still get `ok: true`, and the `signCheckout` test still doesn't throw. The price test keeps passing, as expected. All checks were restored afterwards; no probe code is left in the diff. **Checks run from the repo root:** - `npm run build`: passes. - `npm run typecheck`: passes. - `npm run lint`: one error, the known pre-existing `no-restricted-syntax` in `ceremony/intent-sign/mandates.ts`. Nothing new. - `npm test`: 80 files, 1229 tests, all passing, including `storefront-gate.test.ts`.
