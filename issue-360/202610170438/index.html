#360 An order of 3 × $4.90 is refused at payment: the checkout compares float dollar totals

ready for human review

A shopper ordering 3 × $4.90 through `orders.serve()` currently gets a float order total of 14.700000000000001. The amount-binding gates round the re-derived payable to 14.7 and then require it to equal the unrounded stored total, so a correct payment is refused ("Amount binding: FAIL"). After the fix, line totals, subtotal, discount and total are all rounded to whole cents when the order is built or re-priced. Gate 1 in mandate.ts, dc-payment Gate 1 and reconciliation compare cents-consistent values, so 3 × $4.90 completes the same way 3 × $5.00 does. Tampered amounts and discounts are still refused.

What changed

A shopper buying 3 teas at $4.90 through `orders.serve()` used to have a correct payment refused with "Amount binding: FAIL". The cause was in how the order was built. `orders-serve.ts` added float dollars with no rounding, so the order total came out as 14.700000000000001. The payment checks re-derive the payable amount rounded to whole cents (14.7) and then compare it exactly with that unrounded total. The wallet's signed transaction amount also carried the float artifact. **The fix:** the order is now built and re-priced in whole cents (`toCeremonyLine` and `repriceStored`). The line total, subtotal, discount and total are each rounded with the same `Math.round(n*100)/100` the payment checks use. The discount is also derived the same way the checks derive it (`round2(subtotal × pct/100)`), so subtotal − discount always equals the payable they compute. A 3 × $4.90 order now completes for 14.70, just as 3 × $5.00 completes for 15. The payment checks themselves did not change. They still require the cart total, the re-derived payable and the signed payment to be exactly equal, so an amount 1 cent off or a hand-edited total or discount is still refused. There is no new public API. --- Tests: a new `describe` block in `packages/credentagent-gate/src/orders-serve.test.ts` drives the real `/credentagent/dc-payment/verify` instant-demo route. Three of its tests failed on the unfixed code: the 14.70 payment test, and both 14.69 and 14.71 cases (their "Amount binding" detail showed `14.700000000000001/14.69 vs 14.7`). All pass after the fix. That pre-fix run is the mutation check: with the rounding reverted they fail again. Root checks all pass: `npm run build`, `npm run typecheck`, `npm run lint` and `npm test` (83 files, 1351 tests).
