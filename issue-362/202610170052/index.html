#362 Make the issue agent several times faster without weakening the final review

This makes the issue agent (the pipeline in `ci/issue-agent/` that turns a GitHub issue labelled `agent` into a draft pull request) faster, without weakening the GitHub Claude review that does the final check. Nothing in the published npm packages changes. I confirmed the problem on current main: - The three internal reviewers in `roles.mjs` (the `LENSES` object and `reviewPrompt`) only point at parts of REVIEW.md. They never state its stale-docs rule (§6), its "fix it or flag it" rule (§5), or its "which test fails if this line is reverted?" rule (§2). They also get no diff up front. - Every role runs on one model, `MODEL = ISSUE_AGENT_MODEL` in `run.mjs:49`. - `runGates` runs the full root `npm test` after every fix attempt (`run.mjs:446`). - `checkout()` runs `npm ci` and a fresh build for every worktree, including the "before" checkout used for evidence. - The baseline (main's own gate results) is measured again on every run, even for the same main commit. After the change: - The spec agent and the three reviewers run on a faster, configurable review model. The implementer keeps the main model, and `report.json` records which model each role used. - Fix attempts inside a round run only the affected workspace's tests or the changed test files. - The root `npm test` runs exactly once per round, before the reviews. Nothing is published unless that run passed. - A main commit that was already measured reuses its baseline, and `run.log` says so. - The "before" checkout skips its second `npm ci` when the lockfile is the same. - The README documents all of this. Changes under `.github/` stay out of scope, as the issue says. The issue's instructions concern the pipeline itself, which is the feature here; nothing in it asks to change credentials or tools beyond that. One thing the implementer should know: `mutationCheck` in `run.mjs` only reverts source files under `packages/` and `examples/`. A change made only in `ci/issue-agent/` will hit "tests changed but no source file did — nothing to revert" unless that filter also covers `ci/issue-agent/*.mjs` (test files are already excluded). Widening it is in scope, and this run needs it.
