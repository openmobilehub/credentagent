#387 Should the issue agent be allowed to edit .claude/skills/?

ready for human review

The issue agent currently can't edit anything under `.claude/`, because Claude Code protects that folder on its own. So any issue that needs a skill updated (e.g. `.claude/skills/publish-release/SKILL.md`) ends "[needs human]". This change takes the issue's recommended Option 2. It gives the implementing agent an explicit permission to Edit and Write under `.claude/skills/` only. The rest of `.claude/` (settings, hooks, agents, commands) stays off-limits to the agent. The publish step refuses any change to those paths, just as it already does for `.github/`. A skill edit still goes through the three reviews and a human merge. The CI README and the issue-agent section of CLAUDE.md get one line saying so.

What changed

The issue agent can now edit skills under `.claude/skills/`. It still can never publish a change anywhere else under `.claude/`, or under `.github/`. Until now Claude Code blocked every write under `.claude/`, so any issue that needed a skill updated (for example `.claude/skills/publish-release/SKILL.md` on PR #382) ended "[needs human]" even when the rest of the work was done. This takes the issue's recommended Option 2. **Not confirmed:** whether an explicit allow rule really overrides Claude Code's built-in `.claude/` write protection when running through the Agent SDK. That can't be checked in CI. **Follow-up:** one local `node ci/issue-agent/run.mjs <issue> --no-publish` run on an issue that edits a skill. This caveat is now also written in `ci/issue-agent/README.md` and in the comment above `SKILL_EDITS` in `run.mjs`. What changed: - `ci/issue-agent/run.mjs`: the implementing agent's tools (`WRITE_TOOLS`) now include explicit permission rules (`SKILL_EDITS`) for Edit, Write and MultiEdit on `.claude/skills/**`. Each rule is written in two forms, one relative to the working directory and one relative to the project root. The reviewers are read-only and don't get these rules. No rule names settings, hooks, agents or commands. The publish-refusal message now mentions `.claude/` as well. - `ci/issue-agent/checks.mjs`: `forbiddenPaths` still refuses `.github/` and `.git/`. It now also refuses every path under `.claude/` except `.claude/skills/<something>`, so settings, hooks, agents, commands and `.claude/CLAUDE.md` are all refused. The merge-conflict path (`merges.mjs`) reuses the same function, so a conflict resolution in `.claude/settings.json` is refused too. Lookalikes such as `docs/.claude/...` and `.claudex/...` are not affected. - `ci/issue-agent/README.md` and the "Issue agent" section of `CLAUDE.md` now say what the agent may and may not change, and why: settings and hooks control the agents themselves. The issue contained no instructions that try to change tools, credentials, CI or this process beyond the feature itself. The four new tests failed against the old `forbiddenPaths` before the fix. This round changed only a code comment and README text.
