#420 Issue agent: fix only what blocks, then ask for one re-review

ready for human review

A review calls an agent's pull request ready, with two optional notes. The agent spends another half-hour cycle anyway and pushes a commit that only rewords comments. The agent fixes only what must be fixed before merging, then adds a "review again" label. A ready review goes to a person with the notes listed; a second "needs changes" goes to a person as stuck.

What changed

The issue agent now fixes only what blocks a merge, then asks for one re-review, instead of chasing every optional note. **Before:** every open thread the Claude review opened, optional notes included, sent the agent into another fix cycle, and it answered every one of them. A "💬 Ready — small notes" review with open threads was not treated as done. The default cycle limit was 3. **After:** - **Verdicts.** The verdict reader knows ✅ Ready to merge and ⛔ Needs changes. For one release, a 💬 is read as ✅. - **✅ reviews.** A ✅ goes to a human as ready (`agent:ready-for-human`) right away, even with the bot's inline notes still open. The hand-over comment lists those notes as "no action needed", and no commit is made for them. - **⛔ reviews.** The first ⛔ gets one fix cycle. That cycle's checklist is the summary's "Fix before merging" items plus threads opened by people with write access. The bot's inline notes go to the fixer as `<note>` context only. A second ⛔, after any fix cycle, goes to a human as `agent:needs-human`. - **Thread replies.** The push step replies to and resolves each write-access person's thread, and each bot note the fix actually fixed. A bot note the agent declined or left alone gets no reply and stays open. - **Re-review label.** After a fix cycle that pushed a commit, the push step adds `review:again` once, with the push job's token, creating the label if it's missing. It isn't `agent:in-review`, so it starts no review-loop run. - **Cycle limit.** The default is now 2. `run.mjs`, CLAUDE.md and the issue agent README say so. New pure helpers in `checks.mjs`: `reviewFixCriteria`, `threadReplies` and `reReviewCalls`. `threadsToAnswer` now returns `{ answer, notes, ignored }`. The hand-over text is now `handOverComment` in `report.mjs`. This round I made no code changes. The pipeline's feedback was only "the spec reviewer gave no verdict" for each criterion, with no finding about the code. I re-ran the checks on this checkout: - The root `npm test` passed: 92 files, 1548 tests. - `npm run lint` passed. - The issue-agent suite passed: 221 tests. `npm run build` and `npm run typecheck` passed in the previous round, and the code hasn't changed since.
